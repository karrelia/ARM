# Технічне завдання — АРМ Теплооблік

Документ описує функціонал додатка, що замінює Excel-книгу `ЗБЛ новий сезон.xlsm`.
Прототип (цей репозиторій) реалізує розділи 3.1–3.3; решта — дорожня карта.

## 1. Призначення

Облік відпущеної теплової енергії по будинках теплопостачальної організації за
показниками теплолічильників, порівняння фактичного споживання з нормативним
(метеонормалізація за градусо-добами) та формування звітних бланків.

## 2. Ролі користувачів

| Роль | Права |
|------|-------|
| Оператор | введення показань, друк бланків |
| Інженер | + редагування довідників, перерахунки |
| Переглядач | лише читання, аналітика |
| Адміністратор | користувачі, аудит, налаштування |

## 3. Функціональні вимоги

### 3.1 Довідник будинків/абонентів *(реалізовано)*
Поля з `TabAbon`: код будинку, особовий рахунок, відповідальний власник, адреса,
населений пункт, котельня, № та тип обчислювача, одиниці виміру, дата повірки,
№ витратоміра/ТСП, комерційний/розподільчий облік, частка в ТН, теплове
навантаження (`TabTN`, Гкал/год при −23°).

### 3.2 Введення показань *(реалізовано)*
- вибір будинку; автопідстановка попереднього показника з останнього запису;
- введення: дата (або «контрольне вимірювання»), тривалість (год),
  t середньодобова, поточний показник обчислювача;
- автоконвертація приросту в Гкал; живий перерахунок нормативу і відхилення;
- валідація (поточний ≥ попередній);
- збереження в архів (`TabBaza`).

### 3.3 Нормативний розрахунок *(реалізовано)*
```
Обсяг ТЕ, Гкал = приріст × коеф_одиниці   (МВт 0.86 / ГДж 0.2388 / кВт 0.00086 / Гкал 1)
Q розрахункове = (ТН / 1000) × тривалість × частка × (18 − t_сер) / 41
Різниця = факт − норматив;   % = Різниця / норматив × 100
```
Константи: t_внутр = 18 °C; розрахункова ΔT = 41 (18 − (−23)).

### 3.4 Дашборд-аналітика *(дорожня карта — заміна «Зведеної»)*
Фільтри по котельні/будинку/періоду (заміна слайсерів), графіки факт vs норматив,
динаміка по місяцях, рейтинг перевитрат, підсвітка аномалій.

### 3.5 Звіти та друк *(дорожня карта — заміна `PechatSerii`)*
Генерація бланка-відомості (PDF), пакетний друк за прапорцем «Друк», експорт у XLSX.

### 3.6 Інтеграції *(дорожня карта)*
- імпорт вивантажень із 1С (`TDSheet1`) — заміна Power Query;
- телеметрія Danfoss/Kamstrup (аркуш `DANFOSS`);
- метеоархів для автопідстановки t середньодобової.

### 3.7 Адміністрування *(дорожня карта)*
Користувачі та ролі, журнал змін (хто/коли/що ввів), нагадування про прострочені
повірки приладів.

## 4. Нефункціональні вимоги
- багатокористувацький режим (відсутній в Excel-версії);
- транзакційність і бекапи БД;
- робота у браузері без встановлення Excel;
- журналювання та можливість відкату.

## 5. Технологічний стек
PostgreSQL · FastAPI (Python) · React + TypeScript · генерація PDF/XLSX для звітів.
У прототипі БД — SQLite (через `DATABASE_URL` перемикається на PostgreSQL).
