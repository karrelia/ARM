# АРМ Теплооблік — веб-додаток

Клієнтський (без бекенду) веб-додаток для обліку відпущеної теплової енергії по
будинках — у дизайні та з керуванням, аналогічними прикладу КП «Тепловодсервіс».
Заміна Excel-книги ЗБЛ: введення показань, нормативний розрахунок, аналітика,
імпорт реальної книги `.xlsm` — усе **локально у браузері**.

## Запуск

Потрібен звичайний HTTP-сервер (через `file://` модулі можуть не завантажитись):

```bash
python3 -m http.server 8000
# відкрийте http://localhost:8000/
```

Будь-який статичний сервер підійде (`npx serve`, `php -S`, nginx). Для GitHub
Pages — Source: Deploy from a branch, тека `/ (root)` (файл `.nojekyll` вимикає
Jekyll, щоб `vendor/` віддавалась без змін).

## Власний сервер бригадного збору (`server.js`)

Для роботи командою (старший + кілька робітників) у локальній мережі —
запустіть вбудований сервер (Node.js, **без залежностей**):

```bash
node server.js            # порт 8083 за замовчуванням
PORT=8083 node server.js  # явно
```

Він **і роздає додаток, і зберігає спільні дані**. Пристрої на тому ж Wi-Fi
відкривають `http://<IP-сервера>:8083/` (напр. `http://192.168.1.47:8083/`).

**Авторизація**: при першому запуску створюється **адміністратор (старший)**;
далі він у розділі «Користувачі» додає робітників (ім'я + PIN). Кожен входить
під своїм ім'ям і PIN — воно й підписує показання; **адмін = Старший**,
звичайний користувач = **Робітник**. Список користувачів спільний (на сервері),
PIN перевіряється на пристрої (тож вхід працює й офлайн з кешу).

Робочий цикл (усе працює **офлайн-перше** — лічильники в підвалах без зв'язку):

1. **Старший**: імпортує книгу ЗБЛ → у панелі «Виконавець» → «Опублікувати базу
   на сервер». Розподіляє котельні між робітниками (вибір робітника зі
   **списку**); для великих котелень — «по будинках», щоб віддати окремі
   будинки різним робітникам. «Зберегти завдання на сервер» — і воно
   доходить робітникам автоматично. Робітник бачить своє через «Тільки мої»,
   а решту будинків (поза завданням) може переглядати й знімати, вимкнувши
   фільтр або через пошук у «Вводі».
2. **Робітник**: відкриває адресу сервера, входить → «Завантажити базу з сервера»
   (файл не потрібен) → знімає показання **офлайн** (зберігаються локально,
   у черзі).
3. **Автосинхронізація**: щойно з'являється мережа, черга **сама** йде на сервер,
   а дашборд старшого (прогрес по котельнях/робітниках) **оновлюється наживо**.
   Синхронізацію можна вимкнути або запустити вручну кнопкою.

Дані сервера — у `arm-data/db.json` (у `.gitignore`, тож персональні дані **не**
потрапляють у репозиторій). Без сервера додаток працює як і раніше та має
резервний **обмін файлами** (`.json`) через месенджер.

## Можливості

- **Огляд** — помісячно (селектор звітних періодів): спожито ТЕ за різницею
  показань приладів, закриття місяця (скільки комерційних приладів подали
  показання), динаміка споживання за періодами, порівняння сезон-до-сезону,
  топ споживання, **повірка приладів** (прострочені / найближчі 90 днів) та
  **експорт місячного звіту в CSV**. Обсяг будинку = сума **комерційних**
  приладів обліку; розподільчі (поквартирні) — частка всередині будинку й у
  загальний обсяг не входять.
- **Будинки** — список **згрупований за будинком (адресою)** з лічильником
  приладів обліку; пошук (будинок / адреса / № приладу), фільтр за котельнею,
  сортування, експорт CSV. Клік по будинку відкриває **деталь будинку зі
  списком приладів обліку/абонентів** (№ О/Р, обчислювач, факт / ТН, відхилення).
- **Аналітика** — за обраний місяць, із перемикачем метрики:
  - **Обсяг, Гкал** — споживання по котельнях (частка кожної) із переходом до
    будинків; у деталізації — відхилення факту від нормативу по будинку (там,
    де в книзі є навантаження, тривалість і t сер.).
  - **Питоме, Гкал/ТН** — питоме споживання на одиницю теплового навантаження:
    рейтинг котелень і будинків за інтенсивністю (лише де в книзі є ТН).
- **Ввід** — форма введення показань (блок «Будинок і прилади обліку») з
  автопідстановкою попереднього показника, **живим нормативним розрахунком**
  (факт / Q / різниця / %) і валідацією. Можна додати **кілька фото
  лічильника** (камера або галерея) — вони зменшуються до розміру,
  достатнього щоб розібрати показник (довша сторона ≤ 1280 px, JPEG),
  зберігаються разом із показанням і доступні в архіві та картці будинку.
- **Картка будинку** — архів показань, навігація «← Попер. / Наступн. →»,
  кнопка додати показання.
- **Імпорт** (іконка бази у шапці) — приймає `.xlsm` / `.xlsx`:
  - `Довідники!TabAbon` → будинки/абоненти;
  - `Довідники` (TabTN) → теплове навантаження (за адресою);
  - `Архів!TabBaza` → історія показань (з'єднання за адресою будинку).
- **Бригадний збір** (роль виконавця у шапці) — «Старший» / «Робітник» + ім'я.
  Кожне зняте показання підписується ким/коли знято. У списку «Будинки» —
  **статус збору** кольором: 🟢 знято (всі прилади) · 🟡 частково · ⚪ чекає,
  зі зведенням «Зібрано N / M» та прогресом.
- **Обмін файлами (без сервера)** — у панелі «Виконавець»:
  - Старший розподіляє котельні між робітниками і **експортує завдання**
    (`.json`); робітники його імпортують і бачать «Тільки мої».
  - Робітник **вигружає пакет за день** (`.json` з показаннями + фото) і надсилає
    старшому в месенджер.
  - Старший **імпортує пакети** (той самий значок бази приймає і `.xlsx`, і
    `.json`) — показання **ідемпотентно зливаються** у майстер-базу
    (дедуплікація за особовим+датою, перемагає пізніше зняте, лічильник
    конфліктів, перевірка підпису бази).
  - **Дашборд старшого** (у «Будинки» → «Хто зібрав / що лишилось»): прогрес
    збору **по котельнях** (з призначеним робітником) і **по робітниках**
    (скільки приладів здано / залишилось).
- **Теми** (світла/темна) і **розмір шрифту** — у шапці.
- **Збереження** — база та введені показання зберігаються в **IndexedDB** і
  відновлюються при наступному відкритті.
- Кнопка **«Демо-дані»** на порожньому екрані — для швидкого ознайомлення.

## Розрахунок (порт із VBA книги ЗБЛ)

```
Обсяг ТЕ, Гкал = приріст × коеф_одиниці   (МВт 0.86 / ГДж 0.2388 / кВт 0.00086 / Гкал 1)
Q розрахункове = (ТН / 1000) × тривалість × частка × (18 − t_сер) / 41
Різниця = факт − норматив;   % = Різниця / норматив × 100
```

При імпорті авторитетними є збережені у книзі значення Q; де порожньо — факт
(Гкал) до-обчислюється з приросту показань.

## Структура

| Файл | Призначення |
|------|-------------|
| `index.html` | Сам додаток (шаблон `x-dc` + клас логіки `Component`) |
| `support.js` | Рантайм document-component (рендерить шаблон через React) |
| `vendor/react*.js` | React 18.3.1 (UMD), локально — без зовнішнього CDN |
| `vendor/xlsx.full.min.js` | SheetJS — розбір `.xlsx` / `.xlsm` |

## Технічні нотатки

- React підключено локально (`vendor/`), тож додаток працює офлайн.
- Шрифт Manrope підвантажується з Google Fonts; офлайн застосовується системний.
- Дані нікуди не вивантажуються — увесь розбір і збереження на пристрої.
